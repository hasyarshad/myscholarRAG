# What backs which number

Every figure in the top-level README comes from one of these files. Each is
regenerated by the corresponding script in `scripts/`.

| file | what it measures | the claim it supports |
|---|---|---|
| `generation_phase1.{json,md}` | the ablation, nine configurations over the same 37 questions | naive 51.4%, +hybrid 56.5%, **+prompt 17.3%**, +routing 12.3%, +citations 11.8%, +grounding 8.3% unsupported claims |
| `generation_phase5.{json,md}` | the shipped configuration | **7.8%** unsupported claims, 80% correct refusal, 100% citation validity |
| `retrieval.{json,md}` | dense vs hybrid vs routed | MRR 0.860, hit@1 0.81 |
| `selection.{json,md}` | which papers a question is about | 90% recall of the papers an answer needs |
| `routing.{json,md}` | query classification | 93.5% overall, 100% on bibliographic and out-of-scope |
| `confusable.md` | attribution where several papers cover a subject | 87% correct paper cited, 0% contamination |
| `probe_routing.json` | broadly phrased "work on X" questions | the first entry under Limitations |
| `judge.{json,md}` | the faithfulness judge scored against itself | the self-marking caveat under Results |
| `report.md` | combined summary written by `make eval` | — |

`variance/` holds repeated runs of the shipped configuration, written by
`scripts/variance_run.sh`, which is how run-to-run spread was measured. One of
them is also a **fixture**: `run-1.json` is the run the hand labels in
`tests/eval/labels.yaml` were judged against, and
`tests/unit/test_rubric_agreement.py` reads it to check that the automated metric
agrees with human judgement. Removing it disables those tests silently rather
than failing them.

Two things the numbers do not carry themselves: every measurement uses 37 or
fewer examples, and that 37-question set has informed enough decisions to be a
development set rather than a held-out one.
